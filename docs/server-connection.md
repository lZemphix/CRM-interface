# Подключение к серверу CRM

## Первый запуск

1. Запустите приложение и введите адрес, выданный администратором компании.
2. Рекомендуемый формат — `https://crm.company.ru`; допускается префикс `/api`.
3. Нажмите «Проверить и сохранить», затем войдите учётной записью этого сервера.

Без явного адреса приложение не пытается автоматически подключиться к localhost.
Для локальной разработки можно указать `http://127.0.0.1:8000` и подтвердить HTTP.
`127.0.0.1` означает компьютер, на котором работает **клиент**, а не компьютер разработчика.
Нельзя указывать логин/пароль, query string или fragment в адресе.

Проверка — отдельный `GET <адрес>/health` без паролей и токенов. Ожидается HTTP 200
и JSON `{"status":"ok"}`. HTTP 503 означает, что backend пока не готов. Ошибки сети,
TLS, неожиданный ответ или перенаправление не сохраняют новый адрес. Проверка
`/health` проверяет доступность и формат ответа, но сама по себе не удостоверяет
личность сервера. Проверка TLS-сертификата не отключается; используйте доверенный HTTPS.

HTTP не шифрует пароль и токены. Его подтверждение — предупреждение, не защита:
для рабочего удалённого сервера настройте HTTPS. При старте с уже сохранённым
адресом дополнительная health-проверка не блокирует вход: при недоступности сервера
можно исправить адрес прямо на экране авторизации.

## Смена сервера

На экране входа показан адрес и ссылка «Изменить сервер». Если вы уже внутри CRM,
сначала выполните обычный выход. Во время запроса входа ссылка отключена.
При обязательной смене временного пароля сначала вернитесь к форме входа.

После успешной проверки нового адреса старые запросы останавливаются, локальные
токены очищаются, затем сохраняется адрес и создаётся новый API-клиент, auth repository
и реестр модулей. Открытые экраны и подписки прежнего сервера уничтожаются.
Даже если адрес остался тем же, сохранение настройки требует нового входа.
Если очистка защищённого хранилища или сохранение настройки завершились ошибкой,
форма покажет ошибку, а новый сервер не будет активирован. После отмены возможного
сбоя очистки приложение возвращает свежий клиент прежнего сервера без автовхода.
Это локальная смена подключения, не удаление аккаунта и не гарантия отзыва
уже выпущенных токенов на сервере: для штатного выхода используется `/auth/logout`.

## Хранение и переопределения

- Адрес: `SharedPreferencesAsync`, ключ `crm.backend_url`, обычная настройка ОС.
- Access: оперативная память. Refresh: `flutter_secure_storage`, ключ привязан
  к нормализованному URL. При смене удаляется также старый ключ `refresh_token`.
- Восстановление авторизации после перезапуска не добавлено.
- Приоритет: `--api-url=` → сохранённый адрес → явно заданный `CRM_API_URL` при
  сборке → первоначальная настройка. Сам аргумент запуска не записывается в настройки.

Аргумент `--api-url=https://crm.company.ru` поддерживается существующим launcher.
Если он прописан в ярлыке, то при следующем запуске переопределит выбор интерфейса;
для обычного пользователя запускайте CRM без него. Сборочные переопределения нужны
разработчику, а не каждой компании. Legacy `ApiEndpoint.defaultUrl` сохранён для
совместимости прямого создания API-клиента в тестах; production bootstrap его
не использует как неявный адрес.

После добавления native-плагина настроек нужно полностью пересобрать/перезапустить
приложение; hot reload не регистрирует новый плагин. Настройки локальны для профиля
ОС, не включаются в ZIP релиза и не являются общекорпоративной конфигурацией.
