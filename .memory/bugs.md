# Ошибки интерфейса

## UI-AUTH-001 — Первый символ после смены раскладки не вводится

date: 2026-10-07
status: resolved
target: before-release
tags: auth, login, input, keyboard-layout, windows

Reported:
После смены раскладки через Alt+Shift первый введённый символ не появляется,
даже если текстовое поле сохраняет фокус и после смены раскладки сделать паузу.
2026-10-10 пользователь уточнил: затронуты все поля, включая поиск клиента,
а не только авторизация.

Reproduction:
Сфокусировать поле входа либо поиска клиента, сменить раскладку через
Alt+Shift, отпустить обе клавиши, выждать паузу, напечатать символ.
Первый символ отсутствует по наблюдению пользователя.

Investigation:
Контроллеры полей не пересоздаются при переключении раскладки, глобальных
перехватчиков клавиатуры в Dart нет. Известный аналог Flutter Windows:
https://github.com/flutter/flutter/issues/177822 . Потеря клавиши после Alt
согласуется с включением нативного режима меню; независимое воспроизведение
именно Alt+Shift в Windows ещё не подтверждено.

Fix:
В Windows runner не передаём DefWindowProc команду WM_SYSCOMMAND/SC_KEYMENU
с lParam=0, только если у окна нет нативной строки меню. Это предотвращает
невидимый режим меню для всех полей приложения. Alt+Space (lParam=пробел),
Alt+F4, смена раскладки и собственно текстовый ввод не перехватываются.
SDK и авторизация не изменены.

Verification:
Нужна полная остановка приложения и повторный flutter run -d windows:
изменён нативный C++, hot reload/hot restart его не обновляют.
Проверить обе раскладки, разные порядки отпускания Alt/Shift, несколько
переключений подряд, логин/пароль/поиск, Alt+Space, Alt+Tab, Ctrl+C/V и Tab.
2026-10-10 пользователь подтвердил: баг исправлен. Закрыто по результату
ручной проверки пользователя; независимая проверка всех сочетаний выше
не выполнялась.

## UI-TASK-DRAG-001 — Переполнение содержимого drag-превью из крайней колонки

date: 2026-10-10
status: open
tags: tasks, appflowy, drag-drop, phantom, layout, overflow

Reported:
Обнаружено при widget-тесте, пользователь отдельно не сообщал. Перетаскивание
карточки «Задача клиента» из первой колонки во вторую даёт RenderFlex overflow
на 27 px снизу. Возврат домой уже не отправляет move и не меняет version.

Investigation:
AppFlowy 0.1.2 убирает внешний margin у крайних колонок, поэтому первая шире
внутренних. Превью ограничено исходным размером, а TaskCard меняет компоновку
заголовка при ширине < 200. Вероятна смена компоновки в более узкой колонке;
точную цепочку layout ещё нужно подтвердить. Между внутренними колонками
одинаковой ширины тот же жест проходит без исключений.

Next:
Воспроизвести в работающем Windows UI; отдельно устранить несовпадение размеров
превью без подавления FlutterError и изменения серверного workflow.
Исправление ложного move не решает этот отдельный layout-дефект.
