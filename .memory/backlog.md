## UI-SEARCH-001 — Быстрый локальный отклик поиска клиентов

date: 2026-10-08
status: deferred
tags: customers, search, cache, local-preview, performance

Request:
После MVP оценить немедленное отображение совпадений среди уже загруженных
клиентов и кеширование повторных поисковых запросов.

Constraints:
Локальные совпадения — только предварительный результат. Даже при их наличии
нужно запросить сервер: среди первых 50 клиентов может быть одна Анна, а в БД
ещё несколько. Не выдавать поиск по загруженной странице за полный поиск.
Для кеша определить актуализацию/срок жизни и учесть права и смену сессии.

Plan:
Не реализовывать сейчас. Сохранить серверный поиск с debounce; оптимизацию
планировать по реальной потребности. Отложенные ошибки отдельно: [bugs.md](bugs.md).

## TASK-REALTIME-001 — Уведомления об изменениях вместо периодического опроса

date: 2026-10-10
status: deferred
target: before-release
tags: tasks, realtime, websocket, long-polling, polling, synchronization

Request:
Пользователь утвердил обычный polling сейчас и попросил вернуться до релиза
к более оперативному обновлению через WebSocket или long polling.

Constraints:
Это варианты для выбора, а не требование внедрить оба транспорта. Не менять
backend сейчас. Сохранить обычные HTTP-команды и единый путь GET/применения
снимка, чтобы смена источника уведомлений не требовала переписывать UI задач.

Plan:
С backend-разработчиком выбрать транспорт и контракт уведомлений. Учесть права,
авторизацию/смену сессии, отключения, повторное подключение, пропущенные события
и несколько процессов сервера. Сигнал публиковать после сохранения транзакции;
после переподключения перечитывать актуальную доску. События могут сначала лишь
запускать существующее обновление, без отдельного сложного протокола DTO-дельт.
Polling остаётся текущим MVP-механизмом (FE-14); окончательный транспорт не выбран.
