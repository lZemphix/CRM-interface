# Mock backend

Отдельный FastAPI-сервер для разработки Flutter-интерфейса. Возвращает три
синтетические карточки по образцу `crm_template.html` из `data.py`; PostgreSQL,
Redis и основной backend не нужны. Flutter-код не менялся.

## Запуск

Из корня репозитория:

```bash
cd mock_backend
uv python install 3.14
uv run uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

Нужен установленный `uv`; команды установят Python 3.14 и зависимости.
Затем в другом терминале запустите Flutter обычным способом. Сервер должен работать
на том же компьютере, что и нативный Flutter-клиент: в `ApiClient` уже указан
`http://127.0.0.1:8000`. Порт 8000 должен быть свободен.

Swagger UI: http://127.0.0.1:8000/docs

## Контракт

При подготовке ответов проверены:

- `lib/core/api_client/client.dart` — адрес сервера;
- `lib/modules/customers/repos/customers_repository.dart` — запрос и пагинация;
- `lib/modules/customers/models/customer.dart` и `test/customer_test.dart` — текущий DTO списка;
- `crm_template.html` — состав списка и карточки;
- `Diary.md` — правила о нескольких контактах, заметках, истории ответственных,
  источнике привлечения и отдельных обращениях.

Актуальные серверные схемы/OpenAPI в этом окружении не найдены. HTML-шаблон показывает
желаемые данные, но не задаёт имена полей HTTP API. Сохранён действующий ответ списка,
а новые поля и ручка полной карточки ниже — **предварительный контракт заглушки**.
При появлении настоящего API его потребуется сверить со схемами backend.

`GET /customers?limit=50&offset=0` возвращает **массив**, без обёртки `items`:

```json
[
  {
    "id": 1,
    "full_name": "Анна Петрова",
    "gender": "female",
    "date_of_birth": "1992-03-15",
    "status": "active",
    "primary_contact": "+7 916 233-10-45",
    "primary_phone": "+7 916 233-10-45",
    "primary_branch_name": "Центр",
    "responsible_employee_name": "Ирина Ковалёва",
    "acquisition_source_name": "Instagram",
    "last_interaction_at": "2026-09-17T14:00:00Z"
  }
]
```

`primary_contact` оставлен для текущего Flutter DTO. `primary_phone` выделен отдельно,
чтобы список мог показывать телефон, а не случайный email. `last_interaction_at`
вычислен из отдельных обращений и приходит как точное время с часовым поясом;
давность («2 дня назад») должен вычислить клиент. Дата рождения имеет формат
`YYYY-MM-DD`. Источник привлечения остался в ответе, но по записи в дневнике
вторичная строка списка в будущем должна показывать давность обращения.

`GET /customers/1` возвращает полную карточку: те же поля списка плюс
`primary_branch_id`, `responsible_employee_id`, `acquisition_source_code`,
`referred_by_customer_id`, `referred_by_customer_name`, `registration_method`,
`created_by_employee_id` и массивы:

| Поле | Содержимое |
| --- | --- |
| `contacts` | Телефон, email или Telegram отдельными записями с `type`, `value`, `is_primary` и `id` |
| `notes` | Текст, автор, время создания и возможного редактирования/архивирования |
| `assignment_history` | Прежний и новый ответственный, инициатор, точное время |
| `tasks` | Задачи клиента со статусом, сроком, приоритетом, автором и необязательным исполнителем |
| `interactions` | Исторические обращения с датой, причиной, кампанией и результатом |

Например, у Анны два контакта и две заметки; Максим пришёл по рекомендации Анны;
Ольга зарегистрирована интеграцией. Дата последнего обращения не подменяется
датой заметки или первоначальным источником привлечения. `GET /customers/999`
возвращает `404`.

Заглушка принимает `limit >= 1`, `offset >= 0`; неверные значения дают стандартную
ошибку FastAPI `422`. Эти ограничения не сверены с отсутствующим backend.
За концом списка возвращается `[]`, например при `offset=100`.

`GET /health` возвращает `{"status": "ok"}` — вспомогательная проверка этой заглушки;
формат ответа настоящего `/health` не подтверждён.

Другие ручки, создание, редактирование и авторизация не имитируются. Кнопки
добавления заметки/задачи в HTML-шаблоне пока лишь демонстрационные; mock не
объявляет эти операции готовым серверным контрактом.

## Изменение данных и проверки

Редактируйте список `CUSTOMERS` в `data.py`; с `--reload` сервер перезапустится сам.
Для пустого списка задайте `CUSTOMERS = []`. Данные не сохраняются в БД. У каждой
карточки должен быть хотя бы один контакт; остальные коллекции могут быть пустыми.

Из папки `mock_backend`:

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

Используются стандартные средства [FastAPI](https://fastapi.tiangolo.com/tutorial/response-model/)
для описания ответа и [TestClient](https://fastapi.tiangolo.com/tutorial/testing/)
для проверки HTTP-контракта.
