# Изменение клиента и контактов

В обзоре карточки клиента обе кнопки «Изменить» подключены к реальному API.
Перед открытием формы клиент загружается заново, чтобы редактировать свежую версию.

## О клиенте

Можно изменить ФИО, пол, дату рождения, предпочитаемый филиал и ответственного.
Пол/филиал/ответственного можно снять. Известную дату рождения нельзя очистить;
у старой записи без даты она может остаться незаполненной. Дата передаётся как
календарная строка `YYYY-MM-DD`, без перевода в UTC.

`PATCH /customers/{id}` получает `version` и только изменённые поля.
Пустая форма изменений не отправляет запрос. Для nullable-полей DTO различает
«не менять» и «очистить»: отсутствие `CustomerFieldChange` опускает ключ,
`CustomerFieldChange(null)` отправляет JSON null. Это важно для архивных
ссылок: изменение имени не переназначает прежнего сотрудника/филиал.

Источник привлечения, реферер, способ регистрации и создавший сотрудник
здесь не редактируются: текущий PATCH-контракт таких полей не принимает.

## Контакты

Окно показывает активные контакты; каждый сохраняется отдельно. Есть добавление,
правка значения/подписи/основного признака и архивирование с подтверждением.
Тип существующего контакта неизменяем по контракту; для другого типа нужно
добавить новый контакт. Пустая подпись очищается через JSON null.

- `POST /customers/{id}/contacts` → 201, типизированный контакт с version.
- `PATCH /customers/{id}/contacts/{contact_id}` → 200, version контакта в теле.
- `DELETE /customers/{id}/contacts/{contact_id}` → 204, без version в контракте.

Сервер нормализует значения, проверяет дубли и права, сохраняет минимум один
основной телефон/email и меняет прежний основной контакт того же типа на запасной.
После мутации перечитывается список контактов, а при закрытии окна — карточка,
активность и текущая выборка списка клиентов. Поиск и выбранный клиент сохраняются.

## Ошибки и клавиатура

Нужны `customers.read` и соответствующее право `customers.update` либо
`customers.contacts`; окончательное решение всегда принимает сервер.
403/422 и ошибки дублей показываются в форме без потери ввода.
Конфликт версии, 404, потерянный ответ/5xx или некорректный ответ сохранения
требуют перечитать данные: повторный submit блокируется, черновик остаётся
до закрытия. Версии не выдумываются для старого/mock API без version.

Если перечитать карточку после операции не удалось, прежние вкладки и черновики
остаются смонтированными, но виден текст об устаревших данных. Редактирование
заблокировано до успешного обновления существующей кнопкой карточки.

Esc и Ctrl/Cmd+Enter используют общие [настраиваемые хоткеи](keyboard-shortcuts.md).
Архивирование подтверждается только явной кнопкой. Реальный backend и отдельный
mock-сервер этой задачей не изменены; старый mock может не поддерживать эти ручки.
