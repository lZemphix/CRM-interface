# Поставка, окружение и лицензии

Записи перенесены 2026-09-19. Если Notes не указывает дату исходного решения, date означает дату его фиксации при миграции; точный день принятия неизвестен. Active означает действующее требование, а не гарантию реализации. Открытые вопросы внутри Notes не являются утверждёнными решениями.

## INFRA-01 — Ручная регистрация и лицензии

date: 2026-09-19
status: active
tags: licensing, branch, workstation, grace-period, self-hosted

Decision:
- Лицензирование ограничивает количество активных филиалов компании. Закрытый филиал можно деактивировать и заменить новым в пределах оплаченного лимита. Дополнительно подтверждено лицензирование рабочих мест: в базовую стоимость филиала входят до пяти зарегистрированных рабочих мест, каждое последующее оплачивается отдельно. Технический механизм регистрации и доказательства идентичности рабочего места ещё не выбран.
- Лицензионная проверка не должна останавливать компанию при кратковременной недоступности внутреннего сервера поставщика: предусмотрите автономный льготный период до трёх суток. При просрочке оплаты также допускается льготный период не более трёх суток за один оплачиваемый период, после чего вход блокируется с понятным уведомлением; бизнес-данные не удаляются.

Reason:
Оплата по филиалам/местам должна сочетаться с работой при кратковременном сбое сервера поставщика и сохранностью данных.

Alternatives considered:
Обсуждалась пара company/branch токенов и их привязка; криптографическая схема ещё не выбрана.

Affected areas:
будущий модуль licensing во внутренней CRM поставщика; backend policy

Notes:
Модули оплачиваются на компанию (ARCH-02). Идентичность рабочего места и несколько backend-установок одной компании открыты. Льготные сроки — требования, не уже реализованная проверка.

## INFRA-02 — Обновления и восстановление

date: 2026-09-19
status: active
tags: updates, msix, updater, secrets, backup, deployment

Decision:
- Обновления backend и Flutter-клиента выполняет сотрудник поставщика. До передачи системы первым реальным заказчикам обязательны проверяемые резервные копии и процедура восстановления.
Постоянный мастер-секрет не вшивается в exe; публичный ключ проверки подписи допустим. Лицензия проверяется backend независимо от возможности скачать установщик.

Reason:
Копирование клиентского приложения не должно выдавать права, а обновление — терять данные и настройки.

Alternatives considered:
MSIX/.appinstaller, отдельный updater и автоматическое скачивание сборки обсуждались. Окончательный механизм автообновления не утверждён.

Affected areas:
deployment, будущий updater, лицензирование

Notes:
Действующее правило — обновление сотрудником поставщика. git pull сам по себе не является установленной процедурой бесшовного production-деплоя.

## INFRA-03 — Локальное окружение и PostgreSQL

date: 2026-09-19
status: active
tags: docker, postgres18, wsl, windows, uv, migrations

Decision:
Backend: Python 3.14, uv, FastAPI, SQLAlchemy async/asyncpg, Alembic. PostgreSQL 18+ volume монтируется в /var/lib/postgresql. DB_* приложения явно связываются с POSTGRES_* контейнера. Flutter Windows SDK запускается средствами Windows; WSL используется для кода/backend.

Reason:
Версионное размещение данных PostgreSQL и разные форматы исполняемых файлов Windows/Linux уже вызывали ошибки разработки.

Alternatives considered:
Старый mount /var/lib/postgresql/data для нового образа и прямой запуск .bat/.exe как Linux-программы не подходят.

Affected areas:
docker-compose.yml; core/settings.py; alembic/; README.md; Flutter windows/

Notes:
Запись в журнале о запущенном процессе не доказывает его работу в следующей сессии. Redis планируется, но в текущем Compose только PostgreSQL. Demo seed и HTML-референс не запускать из production main.
