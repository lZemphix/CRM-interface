# Память CRM

Эта директория хранится в Git и относится только к Flutter-репозиторию. Она не синхронизируется с backend. Точка входа — [MEMORY.md](MEMORY.md).

## Уровни

- MEMORY.md: короткое текущее состояние, ограничения и незавершённая работа. Обновлять существующие пункты.
- decisions/: устойчивые решения с причинами, альтернативами и статусами. Искать по ID, тегам или компонентам.
- journal/YYYY-MM.md: хронология значимой работы. Добавлять записи в соответствующий месяц.
- legacy-journal.md: точный неизменённый исходник Diary.md на момент миграции. Только исторический источник; его старые инструкции записи больше не действуют.
- Diary.md в корне: указатель на новую структуру, больше не дневник.
- bugs.md: отложенные ошибки; backlog.md: отложенные улучшения. Не читать автоматически.

Подробную информацию размещайте один раз по назначению; в других уровнях достаточно краткого вывода и ссылки/ID.
Рост journal и decisions не меняет стартовый набор чтения.

## Выборочное чтение

На старте читать только MEMORY.md из этой директории. При работе ориентироваться на retrieval policy в AGENTS.md.
Например, если предстоит изменить авторизацию:

```bash
rg -l -i 'auth|refresh|token|сесси|отзыв' .memory/decisions .memory/journal
rg -n -i 'auth|refresh|token|отзыв' .memory/decisions/backend.md
sed -n '20,55p' .memory/decisions/backend.md
```

Диапазон sed выбирается по фактическим номерам строк из rg. При большом результате сначала сузить файл, тему или тег.
Сначала текущие decisions; журнал уточняет ход событий. Поиск legacy-journal нужен при пропусках/неоднозначности миграции.
Архивная гипотеза не становится активным решением только потому, что найдена поиском.

## Формат decision

Каждая запись имеет стабильный ID и поля date, status, tags, Decision, Reason, Alternatives considered, Affected areas, Notes.
Статусы: active, superseded, deprecated. При замене укажите ID нового решения у старого и наоборот.
Date — известная дата принятия; если она неизвестна, используйте дату фиксации и явно поясните это в Notes или вступлении файла.
Нереализованное требование может быть active; факт незавершённой реализации должен быть явным.
Если альтернативы или причины не зафиксированы, напишите «не зафиксировано», а не изобретайте их.

## Формат journal

Новая запись: заголовок YYYY-MM-DD HH:MM — название, затем type, tags, areas и Summary, Details, Outcome, Related.
Type: decision, implementation, investigation, bugfix, discussion или note.
Время — Asia/Yekaterinburg. При восстановлении истории без точного времени оставляйте только известную дату и пометку time: unknown.
Ретроспектива за 2026-09-14 описывает более ранние обсуждения с неизвестными датами; не считать дату восстановления датой каждого решения.
Статусы реализации/результаты тестов привязаны к моменту записи и не заменяют проверки текущего состояния.
